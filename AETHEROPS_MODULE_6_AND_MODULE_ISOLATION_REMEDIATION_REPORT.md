## 2. Original Module 6 Problem & Reproduction Steps

### 2.1 Problem Description
The Pre-Deployment Dry Run & Risk Engine (Module 6) was previously coupled with the Cloud Deployer (`services/cloud_deployer`) and shared UI endpoints, failing to reliably analyze exact Terraform artifacts generated by Module 8 (IaC Synthesizer) and lacking an independent service boundary, distinct frontend navigation, and robust stale-report protection.

### 2.2 Reproduction Steps
1. Navigate to the dashboard and trigger IaC code generation in Module 8 (`/terraform`).
2. Attempt to inspect pre-deployment dry-run changes.
3. Observe that AI Dry Run and Approval Gate were incorrectly merged into a single coupled view (`/deployment`), or routed to Cloud Deployer simulation endpoints without a dedicated Module 6 contract or independent sidebar entries.

---

## 3. Actual Root Cause Analysis

1. **Coupled Sidebar & Routing**: The sidebar navigation combined AI Dry Run and Approval Gate under a single `/deployment` route (`deployments`), coupling Module 6 and Module 9 with Cloud Deployment.
2. **Missing Independent Backend Boundaries**: Module 6 relied on general deployment planning calls without dedicated `/api/v1/dry-run` and `/api/v1/approvals` endpoints or isolated module contracts.
3. **Frontend Page Overlap**: Frontend views for risk analysis and approvals lacked independent routing isolation, causing context bleed between dry-run generation and deployment execution.

## 5. Module 6 Terraform Plan Analysis & Evidence

Module 6 consumes exact Module 8 IaC artifacts (`files`, `checksum`, `architecture_version_id`, `project_name`, `target_region`) and executes deterministic parsing and risk evaluation over:
- **CREATE**: New resources (VPC, Subnets, EC2, RDS, IAM).
- **UPDATE**: Property modifications (instance classes, security group rules).
- **DESTROY / REPLACE**: Destructive updates requiring resource recreation.
- **NO-OP / READ**: Unchanged configuration or read-only data sources.

---

## 6. Cost, Security, and Risk Scoring

- **Cost Analysis**: Evaluates resource configurations against baseline AWS pricing evidence (EC2 instance types, RDS instance types, storage GB, multi-AZ, ALB). Returns existing vs. proposed hourly and monthly costs, monthly diff, and explicit assumptions. Marked `UNKNOWN` if pricing metadata is unavailable.
- **Security & Operational Analysis**: Scans configurations for public network exposure, security group ingress/egress, IAM permissions, KMS envelope encryption, database exposure, logging, and SPOFs. Each finding includes ID, severity, affected resource, evidence, explanation, impact, and remediation.
- **Deterministic Risk Scoring**: Calculated from destructive changes, resource replacement, data-loss potential, security findings, and cost increases.
- **Stale Report Protection**: Every dry-run report is cryptographically bound to Project ID, Environment ID, Module 8 IaC generation ID, Architecture version, Terraform artifact hash, and plan hash. Stale reports are automatically invalidated.

## 7. Module-to-Module Communication Contracts

1. **Module 8 → Module 6**: Exact IaC artifact bundle, architecture version, project/environment identifiers, generation ID, and artifact checksum.
2. **Module 6 → Module 9**: Dry-run report ID, plan hash, risk score, findings, cost assessment, and report status.
3. **Module 9 → Module 10**: Approved report ID, valid approval record, matching plan hash, and execution authorization.
4. **Module 6 → State Inventory**: Read-only state inspection via explicit request/response schema.
